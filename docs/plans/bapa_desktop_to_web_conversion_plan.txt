BAPA DESKTOP TO WEB CONVERSION PLAN

Purpose
- Convert the desktop FUBCS BAPA workflows into a web application without changing billing mathematics.
- Preserve existing calculations, audit behavior, preview/rollback safety, and reconciliation rules.
- Support both BAPA main and BAPA individual flows as variants of the same billing contract.

Core Rules
- Do not rewrite the billing engine blindly. First document the desktop behavior and match it in web.
- Keep all changes backward compatible with MySQL 5.5.
- Every data-changing action must have:
  - preview SQL
  - rollback SQL
  - stable transaction ID
  - duplicate prevention
  - audit history
  - reconciliation record
- Treat desktop and web as clients of the same billing rules.
- Do not let UI code own the financial logic.

BAPA Main vs BAPA Individual
- Treat both as the same billing family with different account classification and report grouping.
- Main tasks:
  - create bill
  - update bill
  - adjust bill
  - reconcile totals
- Individual tasks:
  - same core calculation path
  - different account scope or ownership grouping
  - separate reporting and filtering rules if required by desktop behavior
- Important:
  - Keep one shared calculator.
  - Use account type rules to branch behavior, not duplicated formulas.

Safe Billing Change Workflow
1. Load the current live record.
2. Recompute using the same desktop rules.
3. Show preview differences.
4. Generate preview SQL.
5. Store a transaction ID.
6. Wait for approval.
7. Apply the change once.
8. Store rollback SQL and audit history.
9. Reconcile the result after posting.

Duplicate Prevention
- Use a stable transaction key from:
  - source system
  - account number
  - bill month
  - record type
  - source-side sequence or OR number
- Reject duplicate posting if the same transaction key already exists.
- Make imports and sync retries idempotent.
