How To Use This Matrix
- Start with repository_analyzer when you need to understand the current desktop behavior.
- Move to solution_architect when you need shared contracts or workflow design.
- Bring in integration_tester when parity or reconciliation must be proven.
- Bring in security_reviewer before anything that writes data, syncs data, or exports accounting entries.
- Bring in release_engineer once the feature is ready for rollout.

Default Workflow
1. repository_analyzer
2. solution_architect
3. integration_tester
4. security_reviewer
5. release_engineer

Exception Rule
- If the work is mainly about offline/mobile synchronization, start with solution_architect and integration_tester after repository_analyzer.
- If the work is mainly about release readiness, start with security_reviewer and release_engineer after the analysis step.
