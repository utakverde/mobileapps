Use this prompt when starting any new utility conversion, analysis, or implementation task.

Primary Instruction
- Treat the desktop utility system as the source of truth.
- Preserve all existing billing calculations and operational behavior.
- Convert the full utility platform to web in a way that keeps all modules, workflows, and reports in harmony.
- BAPA is one account family inside the full platform, not the whole platform.
- The Android mobile app is a first-class peer platform and must sync with the web and desktop systems.

Hard Rules
- Do not change billing math unless the desktop logic proves it is wrong and the correction is explicitly validated.
- Do not invent new accounting behavior.
- Do not post duplicate financial or sync transactions.
- Every write action must support:
  - preview SQL
  - rollback SQL
  - stable transaction identifiers
  - audit history
  - reconciliation
  - idempotent retry
- Keep MySQL 5.5 compatibility.

What To Analyze
- Login and mode selection
- Member services
- Billing section
- Finance section
- Teller section
- Data transfer
- Reports center
- Configuration
- Financial analysis
- System map integration
- Complaints workflow
- Accounting integration

What To Return

- preview/rollback needs
- sync and duplicate prevention rules
- reconciliation checkpoints
- accounting export candidates
- mobile sync checkpoints
- phase 1 implementation prompt

Prompt Template
Use $multi-platform-team-workflow, $shared-contract-governance,
$cross-platform-sync, and $mysql55-safety.

Analyze the desktop utility system and convert it into a harmonious web-based
platform. Start by reading the master harmony plan and module inventory. Then
produce:
- module-by-module desktop-to-web mapping
- shared data contract recommendations
- special account-family rules
- preview/rollback strategy for all write actions
- sync and duplicate-prevention strategy
- audit and reconciliation strategy
- accounting integration approach
- mobile offline-first synchronization approach

If the task is BAPA-specific, treat BAPA as one branch of the full utility
platform and keep it consistent with the shared core. If the task touches
mobile, treat Android as a peer client that shares the same contracts and
reconciliation rules as web and desktop.
