UTILITY MODULE INVENTORY

Purpose
- Inventory the desktop utility application modules so they can be recreated in the web platform.
- Use this as the master reference for desktop-to-web mapping, reporting, sync, and accounting integration.

Scope Note
- This inventory is based on the visible desktop menu structure, project logs, and existing utility planning files.
- The desktop system is larger than BAPA alone.
- BAPA is one account family inside the broader utility platform.

Cross-Cutting Modules

1. Audit Trail
- Track all changes.
- Store before-image, after-image, user, timestamp, and reason.

2. Reconciliation
- Compare desktop and web totals.
- Detect drift in billing, collections, aging, disconnection, and reconnection.

3. Duplicate Prevention
- Prevent duplicate billing, payment, and transfer posting.

4. Sync Queue
- Queue offline changes.
- Retry safely with idempotency.

5. Rollback Handling
- Keep rollback SQL or reversal logic for every write action.

6. Accounting Integration
- Export receivables, collections, adjustments, penalties, refunds, fees, and summaries.

7. Financial Analytics Engine
- Produce trend, variance, and exception analysis for billing and collections.
- Support period-over-period comparisons.
- Expose metrics for finance and management review.

8. Complaints and Case Tracking
- Track complaint status, assignment, response time, and resolution.
- Connect complaint records to consumer accounts and field actions.

9. System Map Integration
- Link consumers, routes, areas, books, and service locations to map or topology views.
- Support operational visualization for dispatch, route planning, and field follow-up.

Web Conversion Strategy
1. Build shared core services.
2. Convert login and mode selection.
3. Convert master data and schedules.
4. Convert billing and collections.
5. Convert reports and logs.
6. Add sync and device transfer.
7. Add reconciliation and audit.
8. Add accounting export.
9. Stabilize and regression test.

Desktop To Web Notes
- Keep billing formulas in one shared engine.
- Split only by account family or workflow rules.
- Avoid duplicating calculations in multiple screens.
- Make every write action previewable and reversible.

End State
- The web app should fully replicate the desktop app’s utility workflow.
- All modules should be available in a browser or as API-backed web pages.
- The platform should support future accounting integration without reworking billing math.
