UTILITY WEB CONVERSION MASTER PLAN

Purpose
- Convert the full desktop utility application into a web-based utility platform.
- Preserve billing calculations, operational workflows, reports, audit history, and reconciliation rules.
- Keep BAPA, regular consumer billing, net metering, collections, disconnection, and reporting as distinct account/workflow families inside one shared platform.
- Support future accounting system integration without changing the billing engine.

Non-Negotiable Rules
- Desktop behavior is the reference standard.
- Web output must match desktop output for the same inputs.
- Preserve existing billing calculations exactly.
- No UI layer may own financial logic.
- Every write action must support:
  - preview SQL
  - rollback SQL
  - stable transaction identifiers
  - idempotent uploads
  - duplicate prevention
  - audit history
  - reconciliation
- MySQL 5.5 compatibility must be preserved.

Preview / Rollback Requirements
- Any write action must first produce a preview record.
- Preview must show before-image, after-image, and reason.
- Apply must use stable transaction IDs.
- Rollback must restore original values using stored rollback SQL.
- Status values should include preview, applied, rolled_back, failed, and rollback_failed.

Duplicate Prevention Rules
- Enforce unique keys by:
  - source system
  - account number
  - bill month
  - record type
  - operation type
  - OR number or source-side sequence where applicable
- Reject duplicate uploads and duplicate posting requests.
- Make sync retries idempotent.

Reconciliation Requirements
- Compare desktop and web totals for:
  - billing
  - kWh
  - collections
  - aging
  - disconnection
  - reconnection
  - new connections
  - lifeline
  - senior
  - net metering
- Track drift by account, bill month, area, and book.
- Flag mismatches for manual review.

Accounting Integration Scope
- Do not replace the billing engine with accounting logic.
- Expose an export/posting interface for:
  - receivables
  - collections
  - adjustments
  - refunds
  - penalties
  - reconnect fees
  - disconnect fees
  - miscellaneous charges
- Support future integration with accounting systems via:
  - CSV export
  - API posting endpoint
  - journal entry mapping
  - summary totals by billing period

Recommended Implementation Order
1. Inventory desktop modules and tables.
2. Define shared contracts and stable transaction IDs.
3. Build read-only parity reports.
4. Implement preview and rollback for write actions.
5. Convert billing, collections, and reports.
6. Add disconnection, reconnection, and scheduling.
7. Add offline sync and duplicate prevention.
8. Add audit and reconciliation views.
9. Add accounting export hooks.
10. Perform regression testing and rollout.

Verification Checklist
- Login mode routes correctly.
- Regular consumer billing matches desktop.
- BAPA main billing matches desktop.
- BAPA individual billing matches desktop.
- Net metering output matches desktop.
- Collections and receipts match desktop totals.
- Scheduling produces the same dates and sequences.
- Reports match desktop totals.
- Preview and rollback work for every write action.
- Duplicate uploads and duplicate postings are blocked.
- Audit history is complete.
- Accounting export is possible without affecting billing math.
